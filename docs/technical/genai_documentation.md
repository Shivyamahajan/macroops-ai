# GenAI Layer — Technical Documentation

**Project:** MacroOps AI  
**Phase:** Phase 03 — GenAI Research Internship  
**Module:** AI Operations Copilot and SOP Assistant  
**Evaluation date:** November 2026

---

## 1. Overview

The GenAI layer of MacroOps AI provides two complementary capabilities:

1. **SOP Assistant:** Answers operational and procedural questions using a Retrieval-Augmented Generation (RAG) pipeline grounded in the project's Standard Operating Procedures (SOPs).
2. **AI Operations Copilot:** Answers quantitative questions about quick-commerce operations using deterministic Python and Pandas tools.

The design separates procedural knowledge retrieval from numerical business calculations. The language model is used for generating SOP-based explanations, while operational metrics are calculated directly from structured datasets.

The system is designed for historical operational analysis and demonstration purposes. It does not represent a production-connected live operations platform.

## 2. Architecture

### 2.1 SOP Assistant — RAG Pipeline

The RAG pipeline follows these stages:

1. **Knowledge ingestion:** SOP documents stored in `data/knowledge_base/` are loaded.
2. **Text chunking:** Documents are divided into smaller overlapping chunks.
3. **Embedding generation:** The `all-MiniLM-L6-v2` sentence-transformer model converts text chunks into vector embeddings.
4. **Vector storage:** Embeddings and document metadata are stored in a ChromaDB collection named `sop_knowledge`.
5. **Retrieval:** User queries are embedded and relevant SOP passages are retrieved using similarity-based retrieval with Maximal Marginal Relevance (MMR).
6. **Answer generation:** Retrieved context is passed to the Qwen2.5 model through Ollama to generate a grounded response.
7. **Fallback handling:** If the language model is unavailable, the system can return retrieved procedural content. If no relevant procedure is found, it returns a no-match response.

**Knowledge base:** 10 text documents covering operational procedures, KPI definitions, and escalation responsibilities.

**Vector database:** `data/vector_db/`

**Collection:** `sop_knowledge`

### 2.2 AI Operations Copilot

The Operations Copilot uses intent-based routing to identify the user's operational question and invoke the corresponding deterministic tool.

The implementation is divided into:

- `src/ai/copilot.py` — intent detection, query routing, SOP handoff, and conversation follow-up handling.
- `src/ai/copilot_tools.py` — deterministic Pandas-based operational calculations.

The copilot supports questions about:

- SLA breach rates
- Worst-performing stores
- Slowest pickers
- Average picking duration
- Rider assignment delays
- Stockouts
- Inventory accuracy
- Overloaded stores
- Exception counts
- Historically at-risk orders
- Individual store summaries

Numerical answers are calculated from structured datasets rather than generated by the language model.

### 2.3 Dashboard Integration

The GenAI features are available through two Streamlit dashboard pages:

- `src/app/pages/page_05_copilot.py` — AI Operations Copilot.
- `src/app/pages/page_06_sop.py` — SOP Assistant.

Both pages are integrated into the main application navigation in `src/app/main.py`.

## 4. RAG Configuration

The implemented retrieval configuration includes:

| Parameter | Value |
|---|---:|
| Embedding model | all-MiniLM-L6-v2 |
| Chunk size | 600 characters |
| Chunk overlap | 100 characters |
| Retrieved chunks (k) | 3 |
| Candidate chunks (fetch_k) | 10 |
| MMR lambda | 0.6 |
| Maximum retrieval distance | 0.60 |
| Vector database | ChromaDB |
| Collection | sop_knowledge |

MMR is used to improve the diversity of retrieved passages. The retrieval distance threshold helps prevent unrelated questions from receiving unsupported procedural answers.

The system uses a strict SOP-grounding instruction so that generated responses are based on retrieved knowledge rather than unsupported assumptions.

A deterministic rule-based response is also available for rider delay and shortage procedures.

## 6. Evaluation Methodology

A custom evaluation dataset was created at:

`tests/genai_eval_questions.csv`

The dataset contains 60 questions:

- 30 SOP questions.
- 30 operational data questions.

The test set includes supported questions, procedural questions, numerical questions, and unsupported questions that the system should reject or identify as unavailable.

The evaluation runner is:

`src/ai/evaluate_genai.py`

It executes the questions and records responses, execution modes, sources, retrieval information, and response latency in:

`reports/genai_eval_raw.csv`

Each response is manually reviewed using three labels:

- **Correct:** Whether the answer addresses the question accurately.
- **Grounded:** Whether the response is supported by the available knowledge or data.
- **Hallucinated:** Whether the response contains unsupported or fabricated information.

The evaluation script calculates answer accuracy, groundedness, hallucination rate, SOP retrieval relevance, mean response time, and the proportion of responses completed within five seconds.

The reported results are based on manual initial reviewer grading and have not undergone independent external validation.

## 7. Evaluation Results

**Evaluation dataset:** 60 questions  
**Evaluation period:** November 2026

| Metric | Observed result | Target | Outcome |
|---|---:|---:|---|
| Answer accuracy | 93.3% | >90% | Achieved |
| Groundedness | 96.7% | >95% | Achieved |
| Hallucination rate | 3.3% | <5% | Achieved |
| SOP retrieval relevance | 96.7% | >90% | Achieved |
| Mean response time | 4.9 seconds | <5 seconds | Achieved |
| Responses under 5 seconds | 66.7% | No specified target | Observed |

All five specified quality targets were achieved in the initial evaluation.

Although the mean response time met the target, only 66.7% of responses completed within five seconds. Generated SOP responses can take considerably longer than deterministic tool responses.

## 8. Design Decisions

### 8.1 Local language model

Qwen2.5:1.5b was selected to support local execution through Ollama while keeping hardware requirements relatively modest.

### 8.2 Deterministic calculations

Numerical operational questions are routed to Python and Pandas tools. This reduces dependence on language-model calculations and makes numerical outputs reproducible from the underlying datasets.

### 8.3 Retrieval-only fallback

If Ollama is unavailable, the SOP Assistant can use retrieved SOP passages instead of requiring language-model generation.

This also supports environments where a local Ollama runtime cannot be deployed.

### 8.4 No-match handling

Unsupported questions should not receive invented answers. Questions unrelated to the SOP knowledge base should return:

`No matching procedure found in the SOPs.`

### 8.5 Safety handling

The damaged-item procedure includes a safeguard: food and other products with compromised packaging, leakage, or signs of spoilage must never be packed.

## 9. Limitations and Known Deviations

1. **Historical data:** Operational metrics and risk results are based on project datasets and are not connected to live quick-commerce systems.
2. **Local model dependency:** Generated SOP responses depend on Ollama and the locally installed language model.
3. **Response latency:** Generated responses can exceed five seconds, particularly for procedural questions.
4. **Evaluation limitations:** The evaluation set contains 60 questions and uses manual reviewer labels. Results may vary with different questions and reviewers.
5. **No independent validation:** The reported evaluation has not yet been independently graded by a second reviewer.
6. **FR-016 scope deviation:** Historical operational trends and live rider availability monitoring were not implemented. The available dataset does not contain a live rider availability field or a live rider-status feed. The copilot therefore reports available historical rider assignment delay metrics rather than current rider availability.
7. **Customer satisfaction:** Current customer satisfaction information is not available in the operational dataset.
8. **Weather information:** Weather questions are outside the scope of the SOP knowledge base and operational copilot.

## 10. Future Improvements

Potential improvements include:

- Independent review of a sample of evaluation responses.
- Increasing the evaluation dataset with more edge cases and paraphrased questions.
- Reducing language-model response latency.
- Improving retrieval quality and answer completeness.
- Integrating live operational data when reliable sources become available.
- Adding rider availability monitoring after a suitable real-time data source is integrated.
- Expanding dashboard monitoring and evaluation reporting.

## 11. Conclusion

The GenAI layer adds a procedural knowledge assistant and a deterministic operational copilot to MacroOps AI.

The RAG pipeline provides SOP-grounded responses with no-match handling and a retrieval-only fallback. The Operations Copilot uses deterministic tools to answer numerical questions about operational performance.

The initial 60-question evaluation achieved all five specified quality targets. The implementation provides a foundation for further testing, performance optimization, and integration with real-time operational systems.
